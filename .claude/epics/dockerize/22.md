# Task: マルチステージDockerfile + .dockerignore の追加

## Description

`cmd/eveping` を静的バイナリとしてビルドし、最小の実行イメージで起動するマルチステージ `Dockerfile` をリポジトリルートに追加する。あわせて `.dockerignore` を追加し、不要なファイルをビルドコンテキストから除外する。このEpicの他タスク(docker-compose.yml、README、CI)はすべてこのタスクの成果物に依存する。

## Acceptance Criteria

- [x] リポジトリルートに `Dockerfile` が追加され、build/runtimeの複数ステージ(マルチステージビルド)になっている
- [x] ビルドステージは `go.mod` の `go 1.24.7` に対応するGo公式イメージを使い、`CGO_ENABLED=0` で `cmd/eveping` を静的バイナリとしてビルドする
- [x] 実行ステージは軽量イメージ(alpine系)を使い、ビルド成果物のバイナリのみをコピーする(Goツールチェインを含まない)
- [x] `EVEPING_DISCORD_TOKEN` の値がDockerfile内にハードコードされていない
- [x] 実行ステージは非rootユーザーでプロセスを起動する(`USER` 命令)
- [x] `.dockerignore` が追加され、`.git`・`.claude/`・ローカルの `.env` 等がビルドコンテキストから除外される

## Test Plan

- [x] `TestDockerfileIsMultiStage` — `Dockerfile` を読み込み `FROM` 命令が2つ以上あることを確認(red: `Dockerfile` 不在で失敗 → green: 追加後成功)
- [x] `TestDockerfileUsesCGoDisabled` — `Dockerfile` に `CGO_ENABLED=0` が含まれることを確認
- [x] `TestDockerfileDoesNotHardcodeToken` — `Dockerfile` に `EVEPING_DISCORD_TOKEN` へ具体的な値を直接代入する記述(例: `ENV EVEPING_DISCORD_TOKEN=<何らかの値>`)が無いことを確認
- [x] `TestDockerfileRunsAsNonRoot` — `Dockerfile` に `USER` 命令が含まれることを確認
- [x] `TestDockerignoreExcludesGitAndClaude` — `.dockerignore` が存在し、`.git` と `.claude` を除外するエントリを含むことを確認
- [x] `TestDockerfileInstallsCACertificates` — `Dockerfile` が `ca-certificates` をインストールしていることを確認(code-reviewで追加)

## Technical Details

- 新規ファイル: `Dockerfile`, `.dockerignore`, `dockerbuild/dockerfile_test.go`(パッケージ `dockerbuild`。テストのみのパッケージとしてリポジトリルート直下 `Dockerfile`/`.dockerignore` を `os.ReadFile` で読み込みテキスト検証する。Dockerデーモン不要で `go test ./...` に組み込める)
- ビルドステージ例:
  ```dockerfile
  FROM golang:1.24-alpine AS build
  WORKDIR /src
  COPY go.mod go.sum ./
  RUN go mod download
  COPY . .
  RUN CGO_ENABLED=0 go build -o /out/eveping ./cmd/eveping
  ```
- 実行ステージ例:
  ```dockerfile
  FROM alpine:3.20
  RUN adduser -D -u 10001 eveping
  COPY --from=build /out/eveping /usr/local/bin/eveping
  USER eveping
  ENTRYPOINT ["/usr/local/bin/eveping"]
  ```
